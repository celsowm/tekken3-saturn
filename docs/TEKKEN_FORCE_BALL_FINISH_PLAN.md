# Finish Tekken Force and Tekken Ball

Both modes run from the full Saturn disc in Mednafen. Force has four stages, the Doctor B. challenge, sound, results and a backup record. Its individual transitions have been exercised with probes, and a continuous four-stage playthrough is still due. Ball has a verified complete CPU match in Mednafen and still needs the original two-controller flow.

## 1. Establish the baseline

- Record the exact mixed-mode disc, build configuration, SDK revision and emulator settings. Use `build/saturn/disc/music.cue` through `scripts/play_mednafen.py` with forced outcomes and probe flags off. Check that the staged disc and its generated image carry all four Force levels, boss packs and both modes' audio and menu assets. Extend the launcher's feature checks for any required assets the existing check misses.
- Run the existing `force_` and `ball_` host tests and the original flow comparisons with their local fixtures. Resolve missing fixtures before counting their cases as passed. Keep the most recent matching baseline for duel, Force and Ball performance. Compare the same input, timing window and scene when measuring a change.
- Use the pinned Tekken3Remake rules and traces first. Use focused USA PS1 captures when an open question concerns order of operations, regional behavior, visuals or sound. Keep imported game data private.

## 2. Finish Tekken Force

1. **Play all four stages from the normal menu in Mednafen.** Use ordinary controller input or replay an ordinary input recording from the start. Check enemy pairings and rebinds, targeting, pickups, timer and score, each boss, loading screens, level 4's staircase, and the final tally and return to menu. Fix a failure at its first reproducible transition and replay that segment before repeating the full run. Also exercise a loss that records the high score and returns through Game Over.
2. **Close the save and challenge loop.** Verify copper, silver and gold carry over across BIOS cold boots and the clear that earns gold ends with the key result. Play a subsequent run with three keys through Doctor B., confirm the rescue result and that the unlock is honored by character select after another cold boot. Check the already-rescued result and a full backup-memory case. Existing probe saves can shorten targeted checks of later branches. Retain a continuous four-stage run as separate evidence.
3. **Verify the busiest scenes.** Check a two-enemy wave, a boss swap and the stage 4 fight for stable frame pacing, correct palettes, audible music and effects, and memory use within the existing budgets. Use the existing rate tools for any regression and compare ordinary duel performance if shared code changes.

## 3. Finish Tekken Ball

1. **Complete select and local multiplayer.** Adapt the original 3 × 7 quick select and confirm the port's flow against the `ball_versus` trace, including P2 joining on the select screen, independently choosing a fighter, changing ball type, and playing through to the rematch or return path. Verify the first CPU game still picks Gon, subsequent games use the eligible pool, and both controllers retain their assigned sides.
2. **Complete mode progression.** Wire the original Arcade unlock threshold for Tekken Ball and the CPU Gon defeat unlock into shared progress and character select. Verify both across cold boots and handle existing `T3BALL` and `T3FORCE` saves. Keep this work limited to the progression needed by these two modes.
3. **Verify scoring, replay and pause in Mednafen.** Finish a live CPU match and a two-player match. Cover all three ball types across the checks, including a neutral bounce, a scoring drop, a guarded charge and a lethal iron-ball touch. Verify the two- and six-replay paths, HUD visibility, the next serve from the losing side, and COMMAND, HOW TO and RESET. Use a short targeted capture to check the damage popup on a charging strike or set. Compare frame order at contact, damage, score and reset against the original. Move the update into the match frame if the documented one-tick delay produces a gameplay difference.
4. **Check presentation and sound.** Compare the squash, shadow, point flash and replay effects against short PS1 captures. Verify serve, bounce, charge and replay audio with stage music on. Fix observable mismatches within Saturn memory and rendering limits. Record any remaining hardware-specific differences, including vibration on a standard Saturn pad.

## 4. Sign off on one full disc

- Rerun the host suite and both mode checks on the final mixed-mode image. Smoke-test intro, Arcade, VS and Practice after changes to shared menus, progression, rendering or audio.
- Repeat both modes' boot, a busy gameplay section, audio and save/load on a real Saturn. Record the console region and loader used. Keep hardware sign-off open until those checks run.
- Record the disc hash, test inputs, results and any accepted differences in both mode documents. Shared rankings, Theater and general costume work are outside this plan.
- Before batches, check `du -sh build assets/imported`. Stay within 5 GB and 20 GB respectively. Keep one candidate and one control, use the installed SDK, and retain screenshots, logs and input traces. Keep any video window short and delete `run.mov` after checking it.
- Use background window capture for interactive Mednafen screenshots. For unattended runs with existing scripted input, `scripts/mednafen_record_frames.py` captures frames without taking input focus. Use headless Ymir when it covers the same check.

## Verification checkpoint

- The Release `build/saturn/disc/music.cue` passed the expanded launcher check for Force stages and enemy packs, mode HUDs, Ball select art and audio. The data track matched all 64,898 sectors of the built ISO. SHA-256 of `music.bin` is `6f13463eed83a571d450b5e0104b40faef4645000c82a2743ad07f07d057b79e`. LibSaturn checkout was `95111453`. Mednafen 1.32.1 used the US region and data-only cache emulation.
- All 19 Force and Ball host tests passed. The full suite had 120 passes, eight fixture-dependent skips and zero failures. The Force flow check matched all 6,671 compared frames. The Ball rule checks matched all 3,783 CPU and 7,571 two-player trace frames. Both traces differ in the two gauge rows at startup frame 68.
- The full disc reached Force combat from the regular menu in Ymir. A level 1 attempt using ordinary pad input showed simultaneous Crow and Falcon enemies and reached score 1,220 before the timer ran out. Mednafen reached the Force selection and first-stage loading screen. Evidence is under `build/force-ball-finish/`.
- The full disc reached a CPU Ball rally in Ymir with the beach ball and Gon on first entry. A longer run reached the next round. On the rebuilt disc, all four matching Ball smoke screenshots were byte-identical to the baseline.
- A Force timeout before the boss could show STAGE CLEAR!! when generic round scoring favored the player, then go to Game Over. The round flow now checks the same boss-phase flag as the Force run's outcome. The regression checks timeouts both before and after that boundary. Replaying the same input on the rebuilt disc in Ymir showed the timer expire with two enemies still alive, then GAME OVER and return to the title. The injection boot could not verify the backup write. Screenshots are in `build/force-ball-finish/force-fixed-loss-sheet.png`. The rebuilt disc passed the launcher check and the ISO sector comparison. Its `music.bin` SHA-256 is `288d603420910af9efbc6c526c9302a49f2e386481f92ef23bbeb548ea628de6`.
- The rebuilt full disc reached Ball combat in background Mednafen sessions. A clean backup produced Gon and stored the first-game flag. A cold boot with the copied backup selected Gun Jack and wrote his met count. Force ran through the full disc's mode menu, took a loss against Crow, returned through GAME OVER and wrote a checksummed high score of 60. The same backup still held the pre-existing Ball record. A later cold boot showed HI-SCORE 60 at the start of Force. No saved emulator state was loaded. Evidence is under `build/force-ball-finish/mednafen-background/`.
- The full-disc Ymir pad replays verified COMMAND and HOW TO opening and returning to a live Ball match with gum and iron balls, respectively. RESET with a beach ball returned to ROUND 1 with both bars restored. The input replay now waits for the HOW TO disc read and uses START to leave the pause menu after closing a page. Both pages also opened in background Mednafen.
- An iron-ball match against Gon in Mednafen reached round three with one win each. The game exposed vertical streaks where the VDP2 backdrop clamped outside the bitmap. Stage 19 now samples a transparent row in unused VRAM for those lines, exposing the existing sky color. The same-input Ymir comparison is in `build/force-ball-finish/ball-sky-comparison.png`. Background Mednafen confirmed the fix during a live beach-ball rally. The rebuilt `music.bin` SHA-256 is `a040ce531e949fe38eace2a652abce907ce2ab7b66bcfd359d7c4c275299733c`, and the rebuilt data track again matched all 64,898 ISO sectors.
- These Mednafen runs used the dummy SDL video backend and a local input adapter attached only to the test process. Native stills and backup RAM were saved without creating a visible window, posting desktop keys or recording movies.
- The same rebuilt disc entered Arcade combat, two-controller VS combat, and Practice with its damage HUD in Ymir. The full host suite still reports 120 passes, eight fixture-dependent skips and zero failures.
- A complete iron-ball match on the rebuilt disc in background Mednafen ended with Paul beating Gon 2–0. The stills show the deciding point, the KO, YOU WIN! and the return to fighter select after START. The run used normal controller inputs with all outcome probes disabled. See `build/force-ball-finish/mednafen-background/ball-full-match.png`.
- The rebuilt disc's Ymir traces counted 1,300 draw completions over Force fields 7,200–8,500 and 934 over Ball fields 5,100–6,899. The trace runs used the default injection timing with SH-2 cache emulation off. Both per-event logs reached capacity and the profiler reported truncation. All requested per-field counter rows were retained.
